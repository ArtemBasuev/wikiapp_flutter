# WikiApp

Приложение-каталог на Flutter: список статей Википедии с поиском и подгрузкой, экран статьи, светлая и тёмная тема, интерфейс на русском и английском, офлайн-режим с кэшированием, раздел «Избранное», экспорт данных и адаптивный интерфейс.

## Предметная область

Каталог статей английской Википедии. Данные берутся из MediaWiki Action API (`https://en.wikipedia.org/w/api.php`), того же источника, что в ЛР1. Моков в приложении нет.

Поля статьи (`ArticleModel`):

| Поле | Что это |
|---|---|
| `id` | номер статьи |
| `title` | название |
| `extract` | вводный абзац обычным текстом |
| `url` | адрес статьи в Википедии |
| `length` | размер статьи в байтах |
| `touched` | дата последней правки (UTC) |
| `categories` | названия категорий |
| `links` | названия связанных статей (только на экране статьи) |

Что умеет приложение:

- **Список всех статей** по порядку названий с подгрузкой новых страниц при прокрутке;
- **Поиск по запросу**, при пустом результате экран «Ничего не найдено»;
- **Экран статьи**: детальная информация со всеми категориями и первыми десятью ссылками на другие статьи (загружаются параллельно);
- **Индикатор загрузки**, а при ошибке — сообщение и кнопка «Повторить»;
- **Сохранение настроек**: переключение темы и языка кнопками в шапке. Настройки сохраняются через `SharedPreferencesWithCache` и читаются до первого кадра (без мигания темы при запуске);
- **Офлайн-режим и локальный кэш**:
  - Успешно загруженные страницы статей сохраняются на диск (`SharedPreferencesAsync`);
  - При отсутствии сети или таймауте приложение показывает сохранённые статьи и плашку «Нет связи с сервером. Показаны сохранённые данные»;
  - Если сети нет и данных в кэше нет — отображается экран ошибки с кнопкой «Повторить»;
- **Избранное**:
  - Добавление и удаление статей из избранного по кнопке со звездой на экране статьи;
  - Сохранение статей целиком (в офлайн-режиме отображаются названия, тексты и категории);
  - Отдельный экран «Избранное»;
- **Экспорт избранного в файл**:
  - Экспорт в CSV-файл (`wiki_favorites.csv`) с помощью условного импорта (`package:web` для браузера, `path_provider` + `dart:io` для мобильных/desktop);
  - В браузере файл отдаётся на скачивание; на нативных платформах (Android) сохраняется в папку загрузок/документов с выводом пути на экран;
- **Адаптивный двухколоночный интерфейс**:
  - Автоматическая перестройка по ширине окна (`MediaQuery.sizeOf(context).width >= 840`);
  - В широком окне (>= 840px) слева зафиксирован список статей, справа — открытая деталь, избранное или подсказка;
  - В узком окне (< 840px) используется классическая одноколоночная навигация.

## Данные и архитектура

Цепочка слоёв: API-клиент / Локальный датасорс → репозиторий → Cubit или Bloc → экран.

```
lib/
  common/
    layout/              adaptive_shell.dart (две колонки), breakpoints.dart (порог 840px)
    navigation/          app_router.dart (go_router, ShellRoute)
    network/             dio_client.dart (адрес, таймауты), load_exception.dart
    platform/            export_result.dart, file_export.dart (условный импорт Web / IO)
    settings/            settings_storage.dart (SharedPreferencesWithCache до первого кадра)
  features/article/data/
    api/                 ArticleApi: сетевые запросы
    data_sources/        NetworkArticleDataSource, LocalArticleDataSource (SharedPreferencesAsync)
    dto/                 ArticleDto (сеть), StoredArticleDto (хранилище)
    mappers/             ArticleDtoMapper, StoredArticleMapper
    article_repository.dart
    favorites_repository.dart
```

- Базовый адрес сервера записан один раз в `DioClient` (с параметром `origin=*`).
- Репозиторий сам выбирает источник: при наличии сети данные запрашиваются с сервера и сохраняются локально, при отсутствии сети читаются из `LocalArticleDataSource`.
- Cubit и Bloc знают только `LoadException` и модели.
- Сгенерированные `*.g.dart` лежат в git. Если менять DTO, их можно пересоздать:

```
dart run build_runner build --delete-conflicting-outputs
```

## Запуск

Приложение поддерживает два обязательных таргета: **Браузер (Chrome)** и **Android**.

Нужен установленный Flutter и доступ в интернет. Проверить окружение можно командой `flutter doctor`.

```
flutter pub get
```

### 1. Первый таргет — Браузер (Chrome)

> **Важно**: флаг `--web-port 8080` обязателен для сохранения локального хранилища `localStorage` между запусками.

```
flutter run -d chrome --web-port 8080
```

### 2. Второй таргет — Android

Для запуска на Android нужен установленный Android Studio, Android SDK и запущенный эмулятор или подключённое устройство в режиме отладки.

```
# Список подключённых устройств и их ID
flutter devices

# Запуск на Android устройстве / эмуляторе
flutter run -d <id>
```

В debug-сборке разрешение `INTERNET` на Android уже включено в манифесте.

### Проверка ARB (Локализация)

```
dart run tool/check_arb.dart
```
